# 記録タブの作り直し（1セットずつ記録） 設計書

## 意図

「とにかく記録が付けやすいアプリにする」。ユーザーはジム・自宅とも **1セット終わるごとに記録している**。ところが今の記録タブは「先に複数行を並べて、まとめて記録」する作りで、使い方と噛み合っていない。ユーザーが挙げた困りごとは3つ。

1. **種目選びに一番時間がかかる**: 部位から探しており、種目ごとに上の欄を開き、部位を選び、プルダウンから探す
2. **重量・回数の欄が小さく、押しにくい**（スペースの問題）
3. **1セット目の重量が2セット目以降に自動で入り、セットごとに重量を変えたとき直すのが面倒**

画面案を見せたうえで、ユーザーは「今のセットだけを大きく表示する」案（案B）を選んだ。ドロップセット・スーパーセットは自宅でも使う。ダンベルの刻みは分からないので、設定で変えられるようにしてほしい、とのこと。

## ゴール

- 同じ重量・回数で続けるセットは **「記録する」1タップ**で記録できる
- 種目は **2タップ**（部位→種目）で選べ、次にやる種目は1タップで選べることが多い
- 重量・回数の操作部は親指で押しやすい大きさ（±ボタンは48px以上、記録ボタンは画面幅いっぱい）
- 先のセットに値を流し込まない。次のセットの初期値は「直前に記録した値」

## やらないこと

- 音声で保存まで実行する（「記録して」など）。音声は今のセットを埋める役のまま
- 分析・履歴・PR・ボリュームの計算方法の変更
- 種目ごとの重量刻み（刻みは全体で1つの設定）
- コース作成・種目登録画面の作り直し

## 失敗とみなすこと（動いても駄目なもの）

- 記録したはずのセットが保存されていない（保存失敗を黙って捨てる）
- よくある流れ（同じ種目を3セット）で、今よりタップが増える
- 既存の記録の見え方・PR・部位別ボリューム・キャラ育成の計算が変わる
- 自宅/ジムの絞り込み、自重種目の体重自動入力、音声入力、休憩タイマーの既存機能がなくなる

## 前提（現状のコード）

- Vanilla JS（ESモジュール・ビルドなし）、IndexedDB、Service Worker（現在 `gachi-fit-v28`）、テストは `node --test`（現在221件）
- 記録タブは `js/views/workout.js` が組み立て、`js/views/workout/exercise-panel.js`（種目ヘッダーと選択）、`js/views/workout/set-entry.js`（行の入力、通常/スーパーセット/ドロップセット、`setBaseWeight`、`fillNextRow`）、`js/views/workout/interval-bar.js`（休憩タイマー。今は「開始」を押して始める）に分かれている
- セットの保存形式: `{ id, workoutId, exerciseId, weight, reps, assistedReps, estimated1RM, targetWeight, createdAt }`。ドロップセットとスーパーセットは `groupId` と `groupType`（`'dropset'`/`'superset'`）を持ち、`js/lib/groupSets.js` が連続する同じ `groupId` をまとめて表示する
- 自宅/ジムの絞り込み（`visibleExercises` など `js/lib/env.js`）は選択・提案だけに使い、名前の解決と集計は全種目を使う決まりがある
- 自重種目（`exercise.bodyweight`）は重量欄に直近の体重（`latestBodyWeight`）を入れる
- 記録済みセットの編集は `js/views/set-editor.js`（モーダル）。削除は「本日のセット」の削除ボタン
- 設定は 管理 > 設定（`js/views/settings.js`、値は `localStorage`）

## 決めたこと

### 1. 画面の構成（上から）

1. **種目ヘッダー**（今と同じく上部に固定）: 部位のラベルと種目名。タップすると種目選択（下記3）が開く。スーパーセット中は「A ⇄ B」と2種目を出す
2. **この種目の今日の記録**: 記録済みのセットを「① 26kg×10」「② 26kg×9」のような小さな札で並べる。ドロップは同じ札の中に「26→20→16kg」のようにまとめる
3. **今のセット**（大きなカード）: 「セット3（前回 24kg×10）」の見出し、重量の行（−／数字／＋）、回数の行（−／数字／＋）。数字は大きく（30px以上）、数字をタップすると数字キーボードで直接入力できる
4. **「記録する」ボタン**（画面幅いっぱい・大きい）と、その横に小さめの **「ドロップ」ボタン**
5. **🎤 音声で入力**（今と同じ。今のセットの重量・回数を埋め、種目名を言えば種目を切り替える。保存はしない）
6. **詳細**（畳む）: 補助回数、メモ
7. その下に今ある「本日のセット」「本日の感想」「場所・時間」（畳んだまま）と、下部固定の休憩タイマー

案Bの画面イメージ（ユーザーが選んだもの）:

```
[胸] ダンベルベンチプレス              ▾
記録済み  ① 26kg×10  ② 26kg×9
┌───────────────────────────┐
│ セット3（前回 24kg×10）         │
│ [−2.5]    26 kg     [＋2.5]     │
│ [ −1 ]    10 回     [ ＋1 ]     │
└───────────────────────────┘
[        記録する        ] [ドロップ]
```

「通常／スーパーセット／ドロップセット」の切替セグメントと、複数行の入力欄・行の追加削除・「まとめて記録」はなくす。

### 2. 記録の動き

- **「記録する」**: 今のセットを1件保存し、札に追加し、**休憩タイマーを自動で開始**する。次のセットの初期値は、いま記録した値
- **初期値の決め方**（今のセットに最初に入る値）
  1. 今日この種目をすでに記録していれば、最後に記録したセットの値
  2. なければ、前回この種目をやった日の1セット目の値
  3. どちらもなければ空（自重種目なら重量に直近の体重）
- **「前回」の表示**: 前回この種目をやった日の、同じセット番号の重量×回数。その日にそのセット番号がなければ出さない
- **刻み**: 重量の ± は設定の「重量の刻み」（初期値 **2.5kg**）。回数は ±1。自重種目も同じ刻みで、表示は体重込みの合計（今の運用と同じ）
- **保存できるのは重量と回数がどちらも0より大きいときだけ**（今と同じ）。足りないときはボタンの近くに理由を出す。保存に失敗したら、札を増やさずエラーを出す
- 札をタップすると既存のセット編集モーダルを開く。モーダルに **「このセットを削除」** を足す（確認あり）
- 保存の形式は今と同じ（新しい項目は増やさない）。`createdAt` は保存した時刻なので、キャラ育成の所要時間の推定がより正確になる

### 3. ドロップセット

- 「ドロップ」を押すと、今のセットを保存し、**同じ札に続けて**（同じ `groupId`、`groupType: 'dropset'`）次の重量を入れる状態にする。休憩タイマーは動かさない
- ドロップ中の今のセットの初期値は、前回この種目のドロップで下げた重量（前回同じ位置のドロップがあれば）。なければ直前の重量から刻み2つ分下げた値
- ドロップの連なりは「記録する」を押すと終わる（その最後の1件も同じ `groupId` に入り、休憩タイマーが動く）
- 最初の「ドロップ」を押した時点の1件目から `groupId` を付ける

### 4. スーパーセット

- 種目選択の中に「スーパーセットにする」を置き、相手の種目（B）を選ぶとA⇄Bの組になる
- 組の間は、Aを「記録する」と自動でBの今のセットに切り替わる（休憩タイマーは動かさない）。Bを記録すると休憩タイマーが動き、Aに戻る
- 組の全セットに同じ `groupId`、`groupType: 'superset'` を付ける（今と同じ形）
- ヘッダーの「A ⇄ B」から「組を解く」で通常に戻る

### 5. 種目の選び方

- 種目ヘッダーをタップすると、画面を覆う選択シートが開く
  - 上に **「次はこれ？」**（後述）を1つ大きく
  - **部位のタブ**（胸・背中・肩・脚・腕・体幹など、登録がある部位だけ）
  - 選んだ部位の **種目タイル**（2列・大きく）。並びは **よく使う順**（直近4週間の記録回数が多い順、同数なら名前順）。直近使った種目には「最近」と小さく付ける
  - コースを選んでいれば、コースの種目をタブの先頭（「コース」）に出す
- タイルを押すとシートが閉じ、その種目の今のセットに切り替わる（**部位1回＋種目1回＝2タップ**）
- 開いたときの部位タブは、いまの種目の部位
- **「次はこれ？」の決め方**
  - コースを選んでいれば、コースの順で今日まだ記録していない最初の種目
  - コースがなければ、今の種目を前回やった日に、その種目の **次に記録した種目**（今日まだやっていないもの）
  - 見つからなければ出さない
- 自宅/ジムの絞り込みは今と同じくこの選択に効く（名前の解決と集計は全種目）

### 6. 設定

- 管理 > 設定に「重量の刻み（kg）」を足す。選択肢は 0.5／1／1.25／2／2.5／5（初期値 2.5）。`localStorage` に保存
- 既存の「既定インターバル秒数」は休憩タイマーの自動開始でもそのまま使う

### 7. 細部の決定（設計者の判断。ユーザーに未確認）

- **コース**: 今と同じく、ホームのコースボタンから記録タブを開くとそのコースが選ばれた状態になる。選択シートの上部に「コース」の切替（選択なし／登録コース）を置き、そこでも選べる。ホームの「AIが今日のコースを提案 → この内容で記録する」は、その種目の並びを**その日だけの一時コース**として扱う（コース扱いなので「次はこれ？」もその順）。選んだコースは `sessionStorage` に日付付きで持ち、タブを移動しても今日のあいだは残る
- **セット番号の数え方**: ドロップの連なり（26→20→16）は**1セット**として数える（札1枚）。「前回の1セット目」「前回の同じセット番号」も、この数え方。ドロップの連なりの値として使うのは**最初の重量**（26）。連なりの後の次のセットの初期値も最初の重量
- **ドロップの初期値**: 前回（この種目でドロップがあった直近の日）の同じ位置のドロップと**同じ下げ幅**を、今の重量から引いた値。前回にその位置がなければ、直前の重量から刻み2つ分下げた値。0以下にはしない
- **ヘッダーの付属表示**: 今あるPR、部位別ボリュームのバー（「自己ベスト！」）、意識ポイントの札は残す（1行に詰めて小さく）。記録するたびに更新する。行ごとの推定1RM表示はなくす（今のセットのカードに小さく出すのは作り手に任せる）
- **スーパーセット**: 今と同じく**2〜4種目**まで組める。記録すると組の次の種目へ進み、組の最後を記録したら休憩タイマーが動いて最初に戻る。組の状態とドロップの連なりの状態は `sessionStorage` に持ち、タブ移動や再読み込みでも同じ `groupId` を使い続ける。組の途中で別の種目を選ぶと組は解ける。スーパーセット中は「ドロップ」ボタンを出さない
- **連なりの終わり**: ドロップは「記録する」か、別の種目に切り替えたときに終わる
- **補助回数とメモ**: セットごとに保存する（`sensoryLogs` もセットごとに1件、今と同じ形）。記録したら空に戻す。ドロップの連なりのセットでは補助回数を出さない

## 作り手に任せること

- ファイルの分け方（今の `set-entry.js` は大きく作り替えになるので、新しいファイルに分けてよい）。純粋なロジック（初期値の決め方、前回の値、次はこれ？、よく使う順、ドロップの初期値）は純粋関数にしてテストする
- 選択シート・札・カードの見た目の細部（色・余白）。アプリの暗い配色とアクセント色に合わせる
- 数字の直接入力の出し方（`inputmode="decimal"` の入力欄で十分）
- 「本日のセット」一覧（下の畳み）と札の両方を残すかどうかの細部。どちらも同じ保存結果を出すこと

## 確認すること

- 単体テスト: 初期値の3段階、前回の同じセット番号、次はこれ？（コースあり／なし／見つからない）、よく使う順、ドロップの初期値、刻みの読み書き
- 実機相当の確認（375px幅）: 同じ種目3セットが「記録する」3回で済む／重量を変えたセットが後のセットに影響しない／ドロップとスーパーセットの保存形式が今と同じで、「本日のセット」と履歴で今まで通りまとめて表示される／休憩タイマーが記録で自動開始し、ドロップとスーパーセットのAでは動かない／自重種目・自宅の絞り込み・音声入力が動く／横スクロールなし
