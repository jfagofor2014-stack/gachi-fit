# アプリ全体の整理・UI刷新 設計書

## ゴール

追加開発の積み重ねで肥大化した画面構成とコードを整理し、「ジムで使う道具」として素直な形にする。機能は原則削らず、置き場所と到達経路を整理する。

## 現状の問題（調査結果）

**UI**
- 記録タブがカード8枚・縦3026px（スマホ表示3.7画面分）。セットを1本入れるまでにカード4枚分スクロールする
- インターバルタイマーが保存ボタンより下にあり、毎セット使うのに往復スクロールが必要
- 遷移先が9個（5タブ＋その他4項目）に分散し、深い階層に主要機能が埋もれている
- ホームのカレンダー日詳細と「振り返り」タブがほぼ同一機能（メモ編集＋セット編集/削除）。実際にユーザーが振り返りタブの存在を認識していなかった

**コード**
- `js/views/workout.js` が633行。通常/スーパーセット/ドロップセット/タイマー/感想/本日一覧が1ファイルに同居
- `js/views/exercises.js` が221行。「種目登録」「場所の登録」「コース」の無関係な3セクションが同居
- 汎用ユーティリティ `escapeHtml` がビュー（`views/exercises.js`）から export され、7ファイルがビューを util として import している。`BODY_PARTS`/`COURSE_MIN_EX`/`COURSE_MAX_EX` も同様
- デッドコード：`js/lib/suggest.js` の `suggestBodyParts`（ホーム改修で参照が消え、テストのみが参照）、`js/views/workout.js` の `opts.initialPart`（唯一の呼び出し元だった部位提案ボタンが廃止済み）

## 全体方針

データモデル（IndexedDBのストア・レコード形状）は一切変更しない。変更はナビゲーション構成・画面レイアウト・ファイル分割・CSSに限定する。既存ユーザーのデータ移行は発生しない。

---

## ① ナビゲーション：9遷移先 → 4タブ

| 新タブ | 内容 | 由来 |
|---|---|---|
| ホーム | 今日の提案（コース選択＋AI提案）、カレンダー、日詳細（過去日の編集）、大会カウントダウン、推定1RM、部位別最高ボリューム | 現ホームのまま |
| 記録 | ②の新レイアウト | 現記録タブ |
| 分析 | 履歴/PR・AIインサイト・ボディ をセグメント切替で1タブに集約 | 現「履歴/PR」「インサイト」「ボディ」 |
| 管理 | 種目・コース・場所・設定 をセグメント切替で1タブに集約 | 現「メニュー管理」「設定」 |

- **「振り返り」タブは廃止**（`js/views/review.js` を削除）。過去日の記録編集はホームのカレンダー日詳細に一本化する。日詳細はメモ編集・セット編集・セット削除をすでに全て備えており、機能欠落は発生しない
- **「その他」タブは廃止**（`js/views/more.js` を削除）。中間ハブ画面をなくし、全機能を4タブから2タップ以内で到達可能にする
- 分析タブ・管理タブは、タブ内上部のセグメントボタンでサブ画面を切り替える単一ビューとする（中間メニュー画面を挟まない）

## ② 記録タブ：案A「セット入力ファースト」

画面を3層に分ける。

**上部固定（`position:sticky; top:0`）— 種目ヘッダー**
- 現在の種目名・部位・PR（推定1RM）・本日ボリューム／過去最高のバーを1つの帯に凝縮
- タップで種目選択パネルを開閉（開くと：コース選択 select → 部位セグメント → 種目 select → 意識ポイントchip）
- パネルは種目を選ぶと自動的に閉じる

**中央（通常スクロール）— セット入力**
- モード切替セグメント（通常／スーパーセット／ドロップセット）
- 通常・ドロップセット：セット行（重量・回数ステッパー、補助トグル、推定1RM表示）＋行の増減
- スーパーセット：種目スロット＋ラウンド表
- 共通メモ、エラー表示、「まとめて記録」ボタン

**折りたたみ（`<details>`）**
- 本日のセット（件数をラベルに表示）
- 本日の感想
- 場所・開始/終了時刻・所要時間

**下部固定（sticky）— インターバルバー**
- 秒数セグメント（60/90/120/180）は折りたたみ内に置き、バー自体は「残り時間表示＋開始/停止」のみ
- 既存の `.tabbar`（高さ60px＋セーフエリア）の上に重ねて配置する。記録タブ表示時のみ `body` に下余白を追加する

既存の挙動で維持するもの：通常モードの重量自動追従（`weightTouched`）、ドロップセットの重量引き継ぎ、ビープ（残り1〜10秒＋0秒の長音）、`patchTodayWorkout` の直列化。

## ③ ファイル分割

**記録タブ**（633行 → 4ファイル）
- `js/views/workout.js` — オーケストレーション（データ取得・レイアウト組立・保存処理・各パネルの結線）
- `js/views/workout/exercise-panel.js` — 種目ヘッダー、コース選択、部位/種目選択、PR表示、ボリュームバー
- `js/views/workout/set-entry.js` — 通常/ドロップセットの行UIとスーパーセットの表UI（どちらも「セットをどう入力するか」の責務）
- `js/views/workout/interval-bar.js` — 下部固定インターバルタイマー

**管理タブ**（221行の `exercises.js` を分割）
- `js/views/manage.js` — 管理タブのハブ。セグメントで下記4つを切り替える
- `js/views/exercises.js` — 種目の登録・一覧のみ
- `js/views/courses.js` — コースの作成・一覧
- `js/views/places.js` — 場所の登録・一覧
- `js/views/settings.js` — 変更なし（管理タブから呼ばれる）

**分析タブ**
- `js/views/analysis.js` — 分析タブのハブ。セグメントで `renderHistory` / `renderInsights` / `renderBody` を切り替える。3ファイル自体は既存のまま流用する

**共通ユーティリティの切り出し**
- `js/lib/html.js` — `escapeHtml`（`views/exercises.js` から移動。7ファイルの import 先を差し替え）
- `js/lib/constants.js` — `BODY_PARTS`、`COURSE_MIN_EX`、`COURSE_MAX_EX`（`views/exercises.js` から移動）

**削除**
- `js/views/review.js`、`js/views/more.js`
- `js/lib/suggest.js` の `suggestBodyParts` と `test/suggest.test.js` の該当テスト（`lastTrainedDateByCategory` はホームのAI提案で使用中のため残す）
- `js/views/workout.js` の `opts.initialPart` 分岐

## ④ CSS整理

- 各ビューに散在するインラインstyle（`style="margin-top:8px"` 等）をユーティリティクラスに置換：`.mt-1`(6px)、`.mt-2`(10px)、`.mt-3`(14px)
- 小型ボタンの繰り返し（`style="min-height:40px;padding:0 12px"`）を `.btn-sm` に集約
- 新規クラス：`.ex-header`（上部固定の種目ヘッダー）、`.interval-bar`（下部固定タイマー）、`.subseg`（分析/管理タブのサブ切替）、`.fold`（`<details>` カードの見た目統一）
- `.tabbar` との重なり回避のため、記録タブ表示時に `body.has-interval-bar` を付与し下余白を確保する

## ⑤ 到達経路の変化（ユーザー影響）

| 機能 | 変更前 | 変更後 |
|---|---|---|
| 種目登録 | その他 → メニュー管理 | 管理 →（種目） |
| コース作成 | その他 → メニュー管理（下部までスクロール） | 管理 → コース |
| 場所登録 | その他 → メニュー管理（中段） | 管理 → 場所 |
| 設定 | その他 → 設定 | 管理 → 設定 |
| 履歴/PR | その他 → 履歴/PR | 分析 →（履歴） |
| インサイト | インサイトタブ | 分析 → インサイト |
| ボディ | ボディタブ | 分析 → ボディ |
| 過去日の編集 | その他 → 振り返り ／ ホームのカレンダー | ホームのカレンダー（一本化） |

## エラーハンドリング

- 種目未登録時の記録タブ：既存どおり「先に管理タブで種目を登録してください」の案内を表示（文言のみ新タブ名に更新）
- 分析・管理タブのセグメント：初期表示は各タブの先頭項目。切替時に該当ビューの `render` 関数を呼び直す
- 記録タブの種目選択パネル：種目が1件もない場合はパネルを開かない（上記の案内表示に留める）

## テスト

- 純粋関数の追加・変更はないため、新規ユニットテストは追加しない
- `suggestBodyParts` の削除に伴い `test/suggest.test.js` の該当4テスト（22・29・36・43行目のブロック）を削除する（現在87件 → 削除後83件。`lastTrainedDateByCategory` の2テストは残す）
- ビュー層は既存方針どおりブラウザで手動確認する。確認項目：
  - 4タブすべてが表示・遷移できる
  - 記録タブ：種目ヘッダーのタップで選択パネルが開閉し種目を変更できる／セットを保存できる／保存後に本日のセットが増える／インターバルバーが下部に固定され開始・停止できる／通常モードの重量自動追従とドロップセットの重量引き継ぎが従来どおり動く
  - 分析タブ：履歴・インサイト・ボディの3セグメントが切り替わる
  - 管理タブ：種目・コース・場所・設定の4セグメントが切り替わり、種目登録とコース作成ができる
  - ホーム：コースボタン・AI提案ボタン・カレンダー日詳細の編集が従来どおり動く
  - スマホ幅375pxで横スクロールが発生しない

## スコープ外

- データモデル・IndexedDBスキーマの変更
- 新機能の追加（コース実施の進捗表示、AI提案の再生成など）
- 種目削除時にセットがカスケード削除されない既知のギャップの修正
