# 音声によるセット記録 設計書

## ゴール

ジムでのセット記録の主動線を手入力から音声に移す。「ベンチプレス100キロ8回」と話すだけでセット入力欄が埋まり、1タップで記録できるようにする。

## 前提・調査結果

- ユーザーの端末は **Pixel 8a（Android Chrome）**。Web Speech API（`webkitSpeechRecognition`）が最も安定して動く環境で、日本語（`ja-JP`）の認識精度も実用的。インストール済みPWAでもマイク権限はオリジン単位で保持される
- 同一ユーザーの別プロジェクト Voice Journal は `MediaRecorder` → Gemini（音声直接入力）方式。**今回は採用しない**。1セッションで20〜30セット記録するため、セットごとに1〜3秒の往復とAPI費用が積み上がるのに対し、Web Speech API はほぼ即時かつ無料
- 記録タブは `js/views/workout.js`（オーケストレーション）＋ `js/views/workout/{exercise-panel,set-entry,interval-bar}.js` に分割済み
- `createSetEntry` は `mode()` / `rows()` / `resetRows(keepWeights)` / `ssExerciseIds()` / `ssRounds()` / `resetSuperset()` / `syncFromSteppers()` / `applyMode()` を返す。行の値は `{weight, reps, assistedReps, assistOn, weightTouched}`、最大6行（`MAX_ROWS`）
- `createExercisePanel` は `selectExercise(exerciseId)` を持ち、種目の切り替えと部位セグメント・PR・ボリューム表示の更新を一括で行う
- 既存の「まとめて記録」は複数行を一度に保存する設計。音声で行を1つずつ埋めてから最後に1回保存する流れと自然に噛み合う
- `createStepper` は先のサイクルで 0 を空欄表示にする変更済み。`set(v)` 経由で値を入れれば表示に反映される

## 中核の設計判断

### 判断1: 自動保存しない。埋めて見せてから1タップ

ジムは音楽・プレート音・話し声で騒がしく、誤認識が起きる。認識結果をそのまま保存すると誤りが記録に残る。音声は**セット入力欄を埋めるところまで**を担い、保存はユーザーの明示的な1タップとする。

それでも現在の「部位選択 → 種目選択 → 重量ステッパー → 回数ステッパー → 記録」から大幅に手数が減る。

### 判断2: ステッパーは残す。役割が入力手段から訂正手段に変わる

誤認識時に該当箇所だけ直せる必要がある。また音声非対応環境・マイク拒否・電波なしのいずれでも記録を続けられる必要がある。手入力の削除はしない。

### 判断3: 解析はブラウザではなく自前の純粋関数で行う

Web Speech API はテキストしか返さない。「ベンチプレス100キロ8回」を `{exerciseName, weight, reps}` に変換する解析を `js/lib/voiceParse.js` に純粋関数として置き、ユニットテストする。

種目名は**ユーザーの登録済み種目リストと照合**する。未知語の推測ではなく既知候補とのマッチング問題になるため精度が出る。

### 判断4: 音声は通常・ドロップセットモードのみ

スーパーセットは「種目×ラウンド」の表形式で、1発話に収まらない。マイクは `#w-normal-block` の中に置き、モード切替で自動的に隠れるようにする。

## ① 音声認識（`js/lib/voice.js`）

ブラウザAPIのラッパー。既存方針どおりユニットテスト対象外とし、ロジックは持たせない。

- `isVoiceSupported(): boolean` — `window.SpeechRecognition || window.webkitSpeechRecognition` の有無
- `startListening({onInterim, onResult, onError}): () => void` — 認識を開始し、停止関数を返す
  - `lang = 'ja-JP'`、`continuous = false`（1セット1発話）、`interimResults = true`
  - `onInterim(text)`: 認識途中の文字列
  - `onResult(text)`: 確定した文字列
  - `onError(code)`: `'no-speech'` / `'not-allowed'` / `'network'` / その他

## ② 解析（`js/lib/voiceParse.js`、純粋関数）

### `normalizeUtterance(text): string`

- 全角数字を半角に変換（`２００` → `200`）
- 全角スペースを半角に統一
- 前後の空白を除去

### `matchExerciseName(text, names): string | null`

`text` と各 `names` の両方から空白を除去したうえで、`text` に含まれる名前を探し、**最も長く一致したもの**を返す。該当なしは `null`。

空白除去により「ベンチ プレス を100キロ」のようにSTTが語間に空白を入れた場合も拾える。最長一致により「ベンチプレス」と「インクラインベンチプレス」が両方登録されていても後者を正しく選ぶ。

### `parseSetUtterance(text, exerciseNames): {exerciseName, weight, reps}`

1. `normalizeUtterance` で正規化する
2. `matchExerciseName` で種目名を特定し、一致した部分を文字列から除去する（種目名に含まれる数字が重量・回数として拾われるのを防ぐ）
3. 単位付きの数値を抽出する
   - 重量: 数値（小数可）＋ `キロ` / `kg` / `㌔`
   - 回数: 整数 ＋ `回` / `レップ` / `rep` / `reps`
4. 抽出済みの部分を文字列から除去する
5. 残った裸の数値を、まだ埋まっていない項目に前から順に割り当てる（重量 → 回数の順）
6. 見つからなかった項目は `null` を返す

これにより次がすべて解釈できる:

| 発話 | 結果 |
|---|---|
| ベンチプレス100キロ8回 | `{ベンチプレス, 100, 8}` |
| ベンチプレス 100 8 | `{ベンチプレス, 100, 8}` |
| 100キロ8回 | `{null, 100, 8}` |
| 100 8 | `{null, 100, 8}` |
| 8回 | `{null, null, 8}` |
| ベンチプレス | `{ベンチプレス, null, null}` |

種目名が `null` の場合は「いま選択中の種目」に対する入力とみなす（同一種目の連続セットではこれが最短）。

## ③ セット入力欄への反映（`js/views/workout/set-entry.js` に追加）

`createSetEntry` の返り値に `fillNextRow({weight, reps}): number | null` を追加する。

**対象行の選び方**: 重量または回数のいずれかが 0 の最初の行（＝まだ埋まりきっていない行）を対象とする。「完全に空の行」ではない点が重要で、これにより「100キロ」「8回」と2回に分けて話しても同じ行が補完される。

- 埋まりきっていない行がなく、行数が `MAX_ROWS`（6）未満なら行を1つ増やして入れる
- 埋まりきっていない行がなく、行数が `MAX_ROWS` に達していれば何もせず `null` を返す
- 値を入れた行の添字を返す
- `weight` が `null` ならその行の重量は変更しない。`reps` が `null` の場合も同様（片方だけの発話に対応）

**実装上の注意**: `rowValues[i]` を直接更新してから `renderRows()` を呼ぶ（既存の `resetRows` と同じ方式）。`createStepper` の `set()` は `onChange` を発火しないため、ステッパー経由で値を入れても通常モードの重量自動追従は起きない。音声入力が意図せず他の行に波及しないという点でこれは望ましい挙動である。

これにより「3セット分を続けて話してから、まとめて1回記録する」という既存のバッチ保存の流れがそのまま使える。

具体例（通常モード・初期3行）:

| 操作 | 結果 |
|---|---|
| 「100キロ8回」 | 1行目に 100 / 8 |
| 続けて「90キロ6回」 | 2行目に 90 / 6 |
| 「100キロ」→「8回」 | どちらも1行目（1回目で重量、2回目で回数を補完） |

## ④ 記録タブのUI（`js/views/workout/set-entry.js` と `js/views/workout.js`）

`#w-normal-block` の先頭に音声ブロックを置く。

```
┌─────────────────────────┐
│  🎤 音声で入力            │  ← 高さ64pxの大きなボタン
├─────────────────────────┤
│ ベンチプレス / 100kg / 8回 │  ← 認識・反映の結果表示
└─────────────────────────┘
   セット1
   重量 [−] 100 [＋]
   回数 [−]  8  [＋]
```

- ボタンをタップすると認識開始。ボタンの文言が「聞いています…」に変わる
- 認識中は途中経過をその下に表示する
- 確定したら解析し、次の空き行に反映する
- 種目名が取れた場合は `exPanel.selectExercise(id)` で種目も切り替える
- 反映後は「ベンチプレス / 100kg / 8回 を入力しました」と表示する
- 認識できた項目が1つもない場合は「聞き取れませんでした」と表示し、行は変更しない

**音声が使えない場合はボタン自体を描画しない**（`isVoiceSupported()` が偽のとき）。この場合UIは従来と完全に同じになる。

## エラーハンドリング

| 状況 | 表示 |
|---|---|
| `not-allowed`（マイク権限拒否） | マイクの使用を許可してください |
| `no-speech`（無音） | 聞き取れませんでした |
| `network`（通信不可） | 通信できませんでした。手入力で記録できます |
| その他のエラー | 認識できませんでした |
| 解析結果が全て `null` | 聞き取れませんでした |
| 行が満杯（6行すべて入力済み） | 行がいっぱいです。記録してから続けてください |
| 種目名が登録済み種目にない | 種目は変更せず、重量・回数だけ反映する |

いずれの場合も既存の行の値は壊さず、手入力での記録を続けられる。

## テスト

新規 `test/voiceParse.test.js`（純粋関数のみ）:

- `normalizeUtterance`: 全角数字の変換 / 全角スペースの統一 / 前後空白の除去
- `matchExerciseName`: 完全一致 / 語間に空白が入った発話 / 最長一致（ベンチプレス と インクラインベンチプレス）/ 該当なしで `null` / 空の候補リスト
- `parseSetUtterance`:
  - 種目＋重量＋回数（単位あり）
  - 種目＋重量＋回数（単位なしの裸の数値2つ）
  - 重量＋回数のみ（種目なし）
  - 回数のみ
  - 種目のみ
  - 小数の重量（`62.5キロ`）
  - `kg` 表記
  - `レップ` 表記
  - 種目名に含まれる文字が数値解析を邪魔しないこと
  - 何も取れない発話で全て `null`

`js/lib/voice.js`（ブラウザAPI）と UI はユニットテスト対象外とし、ブラウザで手動確認する。

手動確認項目:
- 音声ボタンが通常モードで表示され、スーパーセットモードで消えること
- マイク権限を許可して発話 → 行が埋まること（マイクが使えない検証環境では、`parseSetUtterance` の結果を直接 `fillNextRow` に渡して反映を確認する）
- 種目名を含む発話で種目が切り替わること
- 連続で2回話すと2行目が埋まること
- 「100キロ」「8回」と2回に分けて話すと同じ行が補完されること
- 6行すべて埋まった状態で話すとメッセージが出て行が壊れないこと
- 既存の記録挙動（通常モードの重量自動追従、ドロップセットの保存後重量引き継ぎ）が壊れていないこと
- スマホ幅375pxで横スクロールが発生しないこと

## スコープ外

- スーパーセットモードの音声入力
- 音声による保存実行（「記録して」などの音声コマンド）
- 種目登録・コース作成・設定など記録以外の画面の音声化
- 漢数字（`百キロ`）の解釈。Google の日本語音声認識は数値をアラビア数字で返すため、まず不要と判断する
- オフラインでの音声認識（Chrome の音声認識はサーバー送信が前提）
- 音声認識の言語切り替え（`ja-JP` 固定）
