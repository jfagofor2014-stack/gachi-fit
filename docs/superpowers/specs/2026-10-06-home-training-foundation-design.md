# 自宅トレーニングの土台 設計書

## ゴール

ジムをやめて自宅トレに切り替えても、記録・コース・AI提案がそのまま使えるようにする。具体的には次の3点。

1. ジム用の種目と自宅用の種目を**環境（自宅／ジム）の切替**で出し分ける
2. 懸垂・ディップスなどの**自重種目を回数だけで記録**できる
3. お持ちの器具（可変ダンベル最大30kg・EZバー・可変ベンチ・ディップスハンドル付き懸垂マシン）で組んだ**種目とコースのプリセット**を用意する

30kg上限を前提にした漸進支援と、キャラクター育成は別サイクルとし、本書では扱わない。

## 前提・調査結果

- 自宅の器具: 可変式ダンベル（最大30kg）、EZバー、可変式ベンチ、懸垂＋ディップス用ハンドルのマシン、マット敷きの床。バーベル・ラック・マシン・ケーブルはない
- ユーザーはこれまで自重種目を**体重を重量欄に入れて**記録している（例: 体重70kgの懸垂＝`70kg × 8`）。本設計はこの意味を変えない
- 保存条件は `weight > 0 && reps > 0`（`workout.js`）。重量0の自重セットは保存できないため、自重種目は重量欄に体重を自動で入れて解決する
- 重量ステッパーの刻みは 0.5kg。10kgの上乗せをステッパーでやると20タップ要るため、音声での「プラス」指定が実用上必要
- 登録済み種目は `{id, name, bodyPart, category, cuePresets, setPattern}`。種目プリセットは `js/lib/exercisePresets.js`（28件）、コースプリセットは `js/lib/coursePresets.js`（6件）
- 登録済み種目を読む画面は `workout.js` / `home.js` / `courses.js` / `exercises.js` / `history.js` / `insights.js`。**絞り込みが必要なのは選択・提案の画面だけ**で、履歴・集計は全種目を使う
- 記録タブの `createExercisePanel` は `onExerciseChange(exId)` を持つが、`workout.js` は現在これを渡していない
- ジムには10月末まで通うため、移行期間は両環境を使う

## データモデルの追加

種目に2つの任意フィールドを足す。既存のIndexedDBスキーマ（ストア構成・`DB_VERSION`）は変えない。

| フィールド | 型 | 意味 |
|---|---|---|
| `homeOk` | boolean | 自宅の器具でできる。欠落は `true` として扱う（隠さない側に倒す） |
| `bodyweight` | boolean | 自重種目。重量欄に直近の体重が入る。欠落は `false` |

環境設定は `localStorage` の `training_env`（`'home'` / `'gym'`）。**初期値は `'gym'`**（更新しても挙動が変わらない）。読み書きは try/catch で囲み、失敗時は `'gym'` として動作する。

## ① 環境切替

### 純粋関数（`js/lib/env.js`、新規）

- `visibleExercises(exercises, env): Exercise[]` — `env === 'home'` なら `homeOk !== false` の種目だけ、`'gym'` なら全種目
- `courseAvailable(course, exercises, env): boolean` — `'gym'` は常に真。`'home'` は、コースの `exerciseIds` のうち**実在する種目がすべて** `homeOk !== false` のとき真。存在しないID（削除済み種目）は判定から除く
- `visibleCoursePresets(presets, env): Preset[]` — `preset.env === env` のものだけ

### ブラウザ依存（同ファイル）

- `getEnv(): 'home'|'gym'` — `localStorage.training_env`。不正値・例外は `'gym'`
- `setEnv(env)` — 保存。例外は握りつぶす

### UI: ヘッダーの切替

`index.html` の `.app-header` 右側に2ボタンのセグメントを置く。

```
GACHI-FIT                [🏠 自宅][🏋 ジム]
```

- 選択中のボタンを `sel` 表示にし、`aria-pressed` を設定する
- ボタンの高さは40px以上（休憩タイマーを大きくした方針に合わせる）。375px幅で折り返さない
- タップで `setEnv` → 現在のタブを `navigate` で描画し直す。`app.js` は直近の route を保持する

### 絞り込みの適用箇所

**全種目を使う（変更しない）**: 履歴、分析、推定1RM・PRの種目名解決、部位別ボリューム、カレンダーの日別詳細、「本日のセット」の種目名。

**絞り込み後を使う**:

| 画面 | 内容 |
|---|---|
| 記録タブ（`workout.js`） | 部位セグメント、種目セレクト、コース選択、スーパーセットの種目選択、音声の種目名照合。`createExercisePanel` / `createSetEntry` には絞り込み後の配列を渡し、`renderToday` には全種目を渡す |
| ホーム（`home.js`） | コースボタン、AI提案への入力種目、AI応答の名前照合 |
| 管理 > コース | コース作成のスロット選択肢、プリセットチップ（`visibleCoursePresets`）、既存コース一覧（`courseAvailable`） |

コースが一覧に出る条件は `courseAvailable`。記録タブの `courses` と `initialCourseId` の検証にも同じ絞り込みを使う。

自宅環境で絞り込み後の種目が0件のときの案内:

- 記録タブ: 「自宅でできる種目がありません。ホームの『自宅向けの種目とコースをまとめて追加』を押してください」
- 登録済み種目が全体で0件のときは従来の「先に『管理』タブで種目を登録してください」

### 既存種目の印付け（起動時に1回）

`js/lib/exerciseMeta.js`（新規）に `ensureExerciseMeta(getAllFn, putFn, presets)` を置く（`ensureDefaultSetPatterns` と同じ依存注入）。

- `homeOk` が boolean でない種目だけを対象にする（**2回目以降は何も書かない**）
- 名前が種目プリセットに一致すれば、そのプリセットの `homeOk` / `bodyweight` を写す
- 一致しない自作種目は `homeOk: true` / `bodyweight: false`
- `app.js` で `ensureDefaultSetPatterns` のあと、最初の `navigate` の前に実行する

### 種目の手動調整（管理 > 種目）

- 種目の追加フォームに2つのチェックを足す: 「自宅でできる」（初期オン）、「自重種目（体重込みで記録）」（初期オフ）。プリセット候補をタップしたときは、そのプリセットの値で埋める
- 種目一覧の各カードに、状態を表す2つのチップ（`🏠 自宅可` / `自重`）を置き、タップで切り替えて保存する。オフのチップは薄く表示する

### 「自宅向けの種目とコースをまとめて追加」

ホームのコースカードで、**自宅環境かつ表示できるコースが0件**のときだけ、ボタンを出す。現在のコースカードは「種目が1件以上あるとき」にだけ描画されるので、表示条件を「絞り込み後の種目がある、または自宅環境」に広げる（自宅環境で絞り込み後の種目が0件でもカードを出す。その場合は挨拶とこのボタンだけを出し、AI提案ボタンは出さない）。押すと、自宅コースプリセット7件すべてについて、未登録の種目とコースを登録する。

- 種目の登録は既存の `missingExerciseNames` で未登録分だけ
- コースは同名が既にあれば作らない（**何度押しても重複しない**）
- 完了後にホームを描画し直し、「種目N件・コースM件を追加しました」を表示する

登録処理は、いまの `courses.js` の `createFromPreset` 内にあるものを `js/lib/coursePresets.js` に `registerCoursePreset(preset, deps)` として切り出し、チップ経由の1件登録と一括追加の両方から使う。このとき登録する種目には `homeOk` と `bodyweight` を含める。

## ② 自重種目

### 対象

`bodyweight: true` とするプリセット: 懸垂、チンアップ、ディップス、プッシュアップ、足上げプッシュアップ、ぶら下がりレッグレイズ、クランチ、プランク。

### 体重の取得（`js/lib/bodyweight.js`、新規、純粋関数）

`latestBodyWeight(records): number | null` — 日付が最大のレコードの `weight`。同日が複数あれば配列の後ろのもの。0以下・非数のレコードは無視し、該当なしは `null`。

### 重量欄の自動入力（`set-entry.js` / `workout.js`）

`createSetEntry` に内部状態 `baseWeight`（初期0）と、返り値 `setBaseWeight(bw: number|null)` を足す。

1. `syncRowValuesFromSteppers()` で手入力を取り込む
2. 直前の `baseWeight` が自動入力されたままの行（`weight === 前のbaseWeight` かつ `!weightTouched`）を 0 に戻す
3. 新しい `bw` があれば、`weight === 0` の行に `bw` を入れる（`weightTouched` は `false` のまま。セット1を直すと後続行へ追従する既存の挙動を保つ）
4. `baseWeight` を更新して `renderRows()`

`resetRows` は、`keepWeights` が偽のとき、行の重量の初期値に `baseWeight` を使う（保存後も次のセットで体重が入った状態に戻る）。

`workout.js` は `createExercisePanel` に `onExerciseChange` を渡し、選ばれた種目が `bodyweight` なら `setBaseWeight(latestBodyWeight(体重記録))`、そうでなければ `setBaseWeight(null)` を呼ぶ。`bodyWeights` ストアは `renderWorkout` の冒頭で1回読む。

体重が未登録（`latestBodyWeight` が `null`）の自重種目では、重量欄は空のまま、音声ステータス欄に案内を出す: 「体重が未登録です。重量欄に体重を入力してください」。

スーパーセットでは自動入力しない（従来どおり手入力）。

### 音声の「プラス」（`js/lib/voiceParse.js`）

`parseSetUtterance` の返り値に `added: boolean` を足す。

- 重量の直前に `プラス` / `＋` / `+` / `追加` があるとき `added = true`（例: 「ディップス プラス10キロ 8回」「+10キロ8回」）
- それ以外は `false`。単位なしの裸の数値は `added` を立てない
- `added` の有無で `weight` の値自体は変えない（10 は 10 のまま）

`workout.js` の `applyUtterance` で、`parsed.added` が真かつ現在の種目が `bodyweight` かつ体重が取れるときだけ、`weight = 体重 + parsed.weight` として `fillNextRow` に渡す。ステータス表示は「体重＋10kg」の形で出す。それ以外（自重でない種目、体重未登録）は `added` を無視し、数値をそのまま重量として扱う。体重未登録のときは、ステータスに「体重が未登録のため、10kgをそのまま入力しました」と出す。

`fillNextRow` は変更しない（自重種目では行の重量が埋まっているため、「重量または回数が0の最初の行」＝回数が空の最初の行が対象になる）。

## AI提案

`buildCourseSuggestionPrompt` は変更しない。入力の種目一覧を環境で絞るだけで、自宅ではケーブル・バーベル・マシンの種目が候補に出なくなる。部位別の直近実施状況は、絞り込み後の種目が属する部位だけで作る。

## テスト

新規・更新する単体テスト:

- `env`: `visibleExercises`（自宅で `homeOk:false` を除く／`undefined` は残す／ジムは全部）、`courseAvailable`（自宅で不可の種目を含むと偽／削除済みIDは無視／ジムは常に真）、`visibleCoursePresets`
- `exerciseMeta`: 印付け（プリセット一致／自作は `homeOk:true`／既に印のある種目は書かない／2回目は書込み0件）
- `bodyweight`: 最新日付／同日複数は後ろ／0・非数の無視／空配列で `null`
- `voiceParse`: 「プラス10キロ」「＋10キロ」「+10キロ」「追加10キロ」で `added:true`、通常の重量と裸の数値で `false`。**既存テストの期待値に `added:false` を足す**
- プリセット整合性: 全エントリが boolean の `homeOk` を持つ／名前が一意／`bodyweight` なら `homeOk` が真／全コースの種目が実在／**`env:'home'` のコースの種目がすべて `homeOk:true`**／全コースが3〜6種目／コース名が一意

ブラウザでの手動確認:

- ヘッダーの切替で、記録タブの種目・コース、ホームのコースボタンが入れ替わる。履歴とPRはどちらの環境でも全件出る
- 切替が375px幅で折り返さず、タップできる
- 自宅環境で懸垂を選ぶと全行の重量に体重が入り、回数だけで保存できる。保存後も次のセットに体重が入る。非自重の種目に切り替えると自動入力が消える
- セット1の重量を直すと、触っていない後続行へ追従する（既存挙動の回帰確認）
- 音声スタブで「ディップス プラス10キロ 8回」→ 体重＋10kg、「ディップス 8回」→ 体重のまま回数8
- 体重未登録で自重種目を選ぶと、重量欄が空のまま案内が出る
- 「自宅向けの種目とコースをまとめて追加」を2回押しても重複しない
- ジム環境では、これまでと同じ画面・同じ種目が出る

## スコープ外

- ダンベル30kg上限への対応（回数目標・テンポ・片手種目などの漸進支援）— 別サイクル
- キャラクター育成 — 別サイクル
- 器具の登録欄・器具メモ（自宅の器具は種目の `homeOk` に畳み込む）
- 時間で測る種目（プランクの秒数）の記録形式
- 自重種目の体重の自動更新（記録した時点の体重を保存し、後から変えない）
- スーパーセットでの体重の自動入力
